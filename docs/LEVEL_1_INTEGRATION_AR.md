# المستوى الأول — تكامل AqarFlow / CRM / WhatsApp / اختبارات الوكيل

## ما يضيفه الفرع

- محرك المبيعات العقارية الحالي متصل الآن بمسار خادم مخططه هو `POST /api/aqarflow/sales`. المصادقة، وتحديد مساحة العمل، وقراءة العقارات محدودة العدد من قاعدة البيانات، وترتيب حتى 50 مرشحًا، ثم تمرير أفضل خمسة فقط إلى Gemini، والتحقق من مسودة الرد قبل إرجاعها.
- عند عدم وجود عقار مؤهل، يعيد المسار ردًا عربيًا حتميًا دون استدعاء Gemini ودون توكنات مدفوعة.
- واجهة عربية لمساعد المبيعات على `/aqarflow-assistant`، وواجهة مخزون على `/properties` مع API لإضافة العقارات وتعديلها وحذفها.
- إعداد Promptfoo في `promptfoo/aqarflow-sales.promptfooconfig.yaml` لاختبار عقد الرد والحقائق وحقن التعليمات ومسار عدم المطابقة.
- تكامل WhatsApp Cloud API على الخادم فقط: تبادل كود Meta، وتحقق ملكية WABA وأرقام الهاتف من Graph API، ودعم رسالة Embedded Signup التي تحتوي WABA فقط عبر اكتشاف أرقامها في الخادم، وتحقق توقيع Webhook، وتشفير كل رمز مع IV مستقل، ومنع التكرار، وإرسال النص ضمن نافذة الخدمة ذات 24 ساعة.
- ملفات مقترحة لمخطط بيانات العقارات واستهلاك AI وWhatsApp. لا ينفّذ GitHub Actions هجرات SQL ولا تتصل هذه التغييرات بقاعدة البيانات من تلقاء نفسها.
- CI يشغّل اختبارات نواة المبيعات وWhatsApp وPromptfoo وإعادة التوجيه والموافقة، ويتحقق من `npm audit`، ويطبق الهجرات الأربع على PostgreSQL مؤقت مع اختبارات عزل بين المكاتب، ثم ينفذ `next build` و`build:cloudflare`. قاعدة Supabase الحية لا تُعدّل من CI.

## إعداد WhatsApp (خادم فقط)

أضف الأسرار إلى Cloudflare secrets / إعدادات الخادم ولا تحفظها في Git:

- `META_APP_ID`
- `META_APP_SECRET`
- `META_GRAPH_API_VERSION` — القيمة الافتراضية في فرع التكامل `v26.0`؛ تأكد من الإصدار المدعوم داخل لوحة Meta عند تفعيل التطبيق، لأن صلاحية الإصدار والأذونات تتبع حساب Meta الفعلي.
- `META_WEBHOOK_VERIFY_TOKEN` — قيمة عشوائية قوية للتحقق من Webhook.
- `META_TOKEN_ENCRYPTION_KEY` — مفتاح عشوائي Base64 يفك إلى 32 بايت.
- `SUPABASE_SECRET_KEY` أو `SUPABASE_SERVICE_ROLE_KEY` — وصول خادمي للجداول الجديدة.
- `AQARFLOW_WHATSAPP_WORKER_SECRET` (مطلوب لمسار المعالجة الآلي إذا فُعّل لاحقًا).

لا يوجد ربط حي قبل إعداد Meta Business/App، وتفعيل Embedded Signup، وتعيين Webhook URL، والصلاحيات والتحقق المطلوبين من Meta. الإعدادات العامة التي يقرأها Worker وقت التشغيل هي `META_GRAPH_API_VERSION` و`NEXT_PUBLIC_META_EMBEDDED_SIGNUP_CONFIG_ID` (ويمكن توفير `NEXT_PUBLIC_META_APP_ID` كاحتياط؛ الواجهة تستخدم `META_APP_ID` إن كان معرفًا). ضع `META_APP_ID` و`NEXT_PUBLIC_META_APP_ID` بالقيمة نفسها إن ضبطتهما، لأن رمز التفويض يُستبدل باستخدام معرف التطبيق السري في الخادم. لا توجد أسرار حقيقية في هذا PR.

## إعداد Gemini وPromptfoo

- `GEMINI_API_KEY` يبقى على الخادم فقط.
- النموذج الافتراضي هو `gemini-3.5-flash-lite` عبر `AQARFLOW_GEMINI_MODEL`.
- يشغّل الأمر `npm run eval:aqarflow:promptfoo` مجموعة التقييمات. يجب توفير `AQARFLOW_EVAL_URL` كرابط مسار المبيعات في بيئة تطوير، و`AQARFLOW_EVAL_COOKIE` كجلسة خاصة لحساب اختبار داخل مساحة عمل معزولة.
- لا تخزن Cookie في الملفات أو CI، ولا تشغّل التقييم مع جلسة إنتاج أو بيانات عملاء حقيقية. لم يتم تشغيل التقييم الحي ضمن هذا العمل.

## ما لا يثبته CI

نجاح البناء واختبارات الوحدة لا يعني اتصالًا حيًا مع Gemini أو Meta، ولا يثبت صحة الهجرة على القاعدة الفعلية أو سياسات RLS الحية. لا يزال إعداد Meta، وواجهة Embedded Signup، وصندوق رسائل متكامل مع تدفق الرد، وتقييم Promptfoo على بيئة حقيقية خطوات تشغيلية. لا دمج ولا نشر ولا تعديل قاعدة بيانات يحدث من هذا PR.


## بوابة الاختبار الآمن لقاعدة البيانات

يستخدم CI حاوية PostgreSQL مؤقتة لإنشاء أقل مخطط محاكاة مطلوب لـSupabase Auth و`team_memberships`، ثم يطبق هجرات AqarFlow الثلاث بالترتيب ويختبر وجود الجداول، وتفعيل RLS، ومنع القراءة المباشرة لجداول الرسائل والرموز، ومنع الوصول أو استهلاك الحصة عبر مساحة عمل أخرى. هذه محاكاة تكامل لـPostgreSQL وليست بديلًا عن تطبيق الهجرات واختبارات الصلاحيات على فرع Supabase حقيقي قبل الإنتاج.

قبل تفعيل WhatsApp في Cloudflare، يجب إضافة أسرار `META_APP_ID` و`META_APP_SECRET` و`META_WEBHOOK_VERIFY_TOKEN` و`META_TOKEN_ENCRYPTION_KEY`، ومتغير `META_GRAPH_API_VERSION` وإعدادات `NEXT_PUBLIC_META_APP_ID` و`NEXT_PUBLIC_META_EMBEDDED_SIGNUP_CONFIG_ID`. المفتاح `QUVOTO_LEGAL_CONSENT_SECRET` مطلوب كذلك لتوقيع موافقة الشروط. لا توجد أي قيمة سرية معبأة في هذا المستودع.


### ملاحظة Embedded Signup

رسالة الإكمال قد تتضمن `waba_id` دون `phone_number_id`. لذلك تقبل الواجهة WABA ID فقط عند التحقق من مصدر رسالة Meta، ثم يستعلم الخادم عن أرقام الهاتف المرتبطة بحساب الأعمال ويُثبت ملكيتها قبل التخزين. عند عدم تحديد رقم، تُربط الأرقام المكتشفة في WABA؛ وإذا أُرسل رقم محدد، فلا يُربط إلا بعد التأكد أنه تابع لنفس WABA. لا يُقبل عنوان pagination إلا إذا بقي على HTTPS و`graph.facebook.com` وعلى مسار الحساب نفسه.


## الحالة بعد تشغيل PostgreSQL داخل CI — 2026-10-10

- اجتاز الرأس `0cddc3fbce98ec4d335fb3fb81a7c04733da1542` جميع خطوات CI، بما فيها حاوية PostgreSQL مؤقتة، وتطبيق الهجرات الأربع واختبارات RLS/العزل السلبية، و`npm audit`، واختبارات المبيعات/WhatsApp/Embedded Signup/الموافقة/إعادة التوجيه، وبناء Next.js وبناء Cloudflare.
- أُضيف بعد ذلك تغيير إعداد افتراضي فقط لتثبيت إصدار Graph API على `v26.0`، ثم تحديث قراءة إعدادات واجهة Meta لتأتي من متغيرات Worker وقت التشغيل بدل الاعتماد على متغيرات `process.env` المبنية مسبقًا. يجب أن يمر CI من جديد على الرأس الذي يتضمن هذه التغييرات قبل الإغلاق النهائي.
- PostgreSQL في CI محاكاة تكامل مؤقتة وليست مشروع Supabase الحي. ما زالت هجرات AqarFlow غير مطبقة على Supabase؛ لا تغيّر مشروع TOP في هذه الجولة.
- التكامل الحي مع Meta غير مختبر: ما زالت موافقة التطبيق، وAdvanced Access لـ`business_management` و`whatsapp_business_management`، وWebhook URL، وبيانات App/Signup Config، وأسرار Cloudflare مطلوبة. التكوين في CI لا يثبت نجاح التفويض عند عميل Meta فعلي.
