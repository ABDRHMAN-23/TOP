# جرد المسارات والتكاملات الحالية — TOP إلى AqarFlow AI

**المستودع:** `ABDRHMAN-23/TOP`  
**المصدر:** قائمة ملفات Git بتاريخ 2026-10-09.  
**الغرض:** ضمان عدم فقد مسار أو تكامل أثناء التحويل؛ ليس توثيقًا بأن كل endpoint آمن أو يعمل في الإنتاج.

## 1. صفحات المنتج الحالية

| المسار | الوظيفة الحالية / ملاحظة التحويل |
|---|---|
| `/` | صفحة QUVOTO التسويقية، فيها اسم النطاق والأسعار والبيانات المنظمة |
| `/app` | تطبيق إنشاء عروض الأسعار |
| `/login` و`/auth/callback` | بريد OTP وOAuth لـGoogle/Apple وموافقة قانونية على الدخول |
| `/dashboard` و`/workspace` | لوحة المقاول وبيانات العملاء/الأعمال/المتابعات |
| `/customers/[id]` | صفحة عميل |
| `/q/[token]` | عرض عام للعميل بواسطة token |
| `/pricing` و`/rewards` | الاشتراكات والمكافآت والإحالات |
| `/team` و`/team/invite/[token]` | أعضاء الفريق ودعوات الانضمام |
| `/advisor` و`/analytics` | مستشار الأسعار والتحليلات |
| `/settings` و`/dashboard/profile` | إعدادات وملف المستخدم |
| `/super-admin` و`/super-admin/discounts` | أدوات إدارة/خصومات داخلية |
| `/terms` و`/privacy` | وثائق قانونية يجب إعادة كتابتها لـAqarFlow |
| `/robots.txt` و`/sitemap.xml` و`/manifest` | SEO وPWA للعلامة الحالية |

هذه الصفحات ليست قابلة لإعادة الاستخدام تلقائيًا لأن بعضها يحتوي منطقًا تجاريًا خاصًا بعروض الأسعار والفوترة.

## 2. جميع ملفات API route التي ظهرت في شجرة Git (22)

| Endpoint | مجال العمل الحالي | قرار التحويل المبدئي |
|---|---|---|
| `/api/admin/discounts` | إدارة أكواد الخصم | استبداله بإدارة منصة عقارية فقط إذا بقيت الحاجة |
| `/api/advisor` | مستشار الأسعار/المشاريع | مراجعة الغرض وإعادة بناء لخدمة توصية العقارات |
| `/api/analytics` | تحليلات QUVOTO | إعادة بناء مقاييس المكتب والـ pipeline |
| `/api/analyze` | تفريغ صوت واستخراج عناصر عرض سعر عبر Gemini | لا يُعاد استخدامه دون بوابة مصادقة وحصة وتحديد معدل |
| `/api/billing/checkout` | إنشاء checkout في Lemon Squeezy | المحافظة على المزود فقط بعد اعتماد اشتراك المكتب |
| `/api/billing` | حالة/إدارة الفوترة | مراجعة نطاق الاشتراك الحالي المرتبط بالمستخدم |
| `/api/billing/webhook` | استقبال أحداث Lemon Squeezy | تحقق التوقيع، idempotency، وربط المعرفات مع نموذج فوترة المكتب |
| `/api/market-data` | جلب بيانات سوق/أسعار | مراجعة المصدر وحدود الاستخدام والتكلفة |
| `/api/notifications` | إشعارات التطبيق | إعادة بناء الإشعارات حسب المكتب والمستخدم |
| `/api/push/subscribe` | Web Push | إعادة الموافقة وإدارة الاشتراكات والنطاقات |
| `/api/quote-intelligence` | تحليل/ذكاء عروض الأسعار | استبدال دلالي بخدمة العقارات فقط إذا كان ذلك معتمدًا |
| `/api/quotes` | إنشاء عرض سعر عبر RPC `create_quote` | لا يُعاد استخدامه كـproperty API |
| `/api/quotes/accept` | قبول عرض عام | إزالته أو استبداله وفق تدفق الطلب العقاري الجديد بعد تحديد المتطلبات |
| `/api/quotes/email` | إرسال عرض للعميل | استبداله بتواصل عقاري بموافقة صريحة ومراقبة |
| `/api/quotes/extras` | إضافات/عمليات مرتبطة بالعرض | مراجعة كل action قبل قرار الإزالة |
| `/api/quotes/photos` | صور العروض وStorage | استبداله برفع صور العقار والمرفقات مع عزل الملفات |
| `/api/quotes/status` | حالات عرض السعر | لا تعاد تسميته دون mapping لدورة lead/deal |
| `/api/referrals` | إحالات ومكافآت | ميزات QUVOTO الحالية؛ لا تُربط بحوافز عقارية دون قرار |
| `/api/settings/business` | إعدادات نشاط المقاول | قد تصبح إعدادات مكتب، لكن المخطط الحالي user-scoped |
| `/api/team/invite` | إنشاء دعوة فريق | يجب تحويله إلى عضوية workspace مع صلاحيات وtoken آمن |
| `/api/team` | أعضاء فريق المقاول | يتطلب إعادة تصميم للعضويات متعددة المكاتب |
| `/api/workspace` | عملاء وعناصر محفوظة وقوالب وأعمال ومتابعات وإحالات | تفكيكه إلى APIs ذات نطاقات أعمال واضحة بدل استخدامه كمخزن عام |

القائمة أعلاه مأخوذة من شجرة الملفات. يجب مراجعة كل handler قبل تحديد هل يحتاج auth أو خدمة خارجية أو صلاحية خاصة؛ أسماء المسارات وحدها لا تثبت سلوك الأمان.

## 3. التكاملات الخارجية

| التكامل | مواضع مبدئية في الشفرة/الإعدادات | قرار التحويل |
|---|---|---|
| Supabase Auth | `lib/supabase/client.ts`, `server.ts`, `proxy.ts`, `app/login`, `app/auth/callback` | تأكيد OAuth/OTP والـ callback allowlist وآلية الموافقة |
| Supabase PostgreSQL | جميع API وRPC `create_quote` ووظائف `app_private` | إضافة مخطط عقاري جديد فقط بعد النسخ الاحتياطي وتصميم tenant isolation |
| Supabase Storage | `business-logos`, `quote-photos` | جرد الملفات وقرار العام/الخاص وحدود MIME/الحجم |
| Gemini | `app/api/analyze/route.ts`; أسرار وأسماء النماذج في `wrangler.jsonc` و`.env.example` | إعادة بناء الوكيل مع quotas وسقف token/cost |
| Lemon Squeezy | `app/api/billing/checkout`, `app/api/billing/webhook` | اعتماد صاحب الاشتراك: المستخدم أم المكتب |
| Resend | `app/api/team/route.ts` يقرأ `RESEND_API_KEY` و`RESEND_FROM_EMAIL` | إضافة المتغيرات إلى جرد التشغيل؛ لا نعرف إعدادات Cloudflare الفعلية |
| Web Push | `lib/push.ts`, `app/api/push/subscribe`, متغيرات VAPID | قرار إن كان مطلوبًا في النسخة العقارية الأولى |
| Cloudflare Workers + R2 | `wrangler.jsonc` و`open-next.config.ts` | إبقاء النشر على `main` محميًا؛ مراجعة اسم Worker وR2 cache قبل أي إعادة تسمية |

## 4. مصفوفة البيانات الحالية → قرار مبدئي

- `quotes`, `quote_photos`, `quote_templates`, `invoices`, `followups`, `jobs`: تبقى legacy إلى حين التحقق من الروابط العامة وPDF والـ RPC.
- `customers`: لا تتحول تلقائيًا إلى `leads`; نموذج العميل المحتمل يحتاج مصدرًا ومرحلة وتعيينًا وميزانية وموافقة تواصل.
- `team_memberships` و`team_invites`: نموذجها owner/member لا يثبت دعم عدة مكاتب لكل مستخدم.
- `subscriptions` و`usage`: مربوطة حاليًا بمعرف مستخدم والاستخدام المتعلق بالعروض؛ تحتاج قرارًا حول اشتراك المكتب وحدود AI.
- `profiles`, `notifications`, `legal_consents`: قد يعاد استخدامها بعد تدقيق دورة الحياة والصلاحيات والخصوصية.
- جداول الإحالات والخصومات: لا تُحذف؛ تبقى دون استخدام في AqarFlow إلى حين اتخاذ قرار.
