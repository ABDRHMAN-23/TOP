# مكتبة المعرفة البيعية — AqarFlow AI

## الغرض

تُحوّل هذه المكتبة مبادئ المبيعات الاستشارية والإقناع المسؤول والتفاوض وكتابة الرسائل وخدمة العملاء إلى تعليمات تشغيلية أصلية. يُرسل إلى النموذج عدد قليل من البطاقات ذات الصلة برسالة العميل بدل إرفاق كتاب كامل أو إرسال المكتبة كلها في كل طلب.

## حدود الاستخدام

- هذه البطاقات صياغة أصلية من AqarFlow، مستلهمة من مجالات عامة في البيع والتفاوض والتسويق، وليست نسخًا من فصول الكتب.
- ذكر مرجع مثل SPIN Selling أو Influence لا يعني أن هناك ترخيصًا لنسخ النص المحمي، ولا يعني أن النموذج ضُبط بدقة على الكتاب.
- المكتبة **توجّه قرار الرد** ولا تستبدل مخزون العقارات الموثق أو صلاحيات المكتب أو ضوابط الخصوصية.
- تحتفظ كل بطاقة بهدف ووقت استخدام وإجراءات عملية وسلوكيات ينبغي تجنبها. يمكن تعديل البطاقات واختبارها دون تغيير كود نموذج اللغة.

## البطاقات التشغيلية

| المجال | مبدأ العمل | ما تمنعه البطاقة |
|---|---|---|
| اكتشاف الاحتياج | فهم ما يهم العميل قبل عرض الخيارات | الأسئلة الكثيرة والاستنتاجات الشخصية |
| اعتراض السعر | تمييز حد الميزانية عن اعتراض القيمة أو المقارنة | الجدال واختلاق الخصومات |
| شرح القيمة | ربط ميزة موثقة بحاجة صرّح بها العميل | المبالغة أو تخيل مزايا غير موثقة |
| البدائل | تعديل شرط مرن بموافقة العميل عند غياب التطابق | تبديل الميزانية أو تجاهل الشروط الثابتة |
| البديل القريب من الميزانية | خيار واحد ضمن سقف مسموح مع كشف السعر والزيادة | تصوير السعر الأعلى كأنه داخل الميزانية |
| المقارنة بالمنافس | مقارنة عادلة ومسنودة بالحقائق | تشويه المنافس أو ادعاء التفوق بلا دليل |
| التفاوض | فهم الطلب والعمل ضمن صلاحيات المكتب | وعد بخصم أو قرار غير مصرح |
| التردد | إزالة غموض واحد وترك القرار للعميل | الندرة المصطنعة والضغط المتكرر |
| بناء الثقة | تقديم أدلة وحدود المعرفة | ضمان قانوني أو مالي غير مثبت |
| إصلاح الخدمة | تصحيح سوء الفهم أو التصعيد | لوم العميل أو الاعتذار عن واقعة غير معروفة |
| الأدب والحدود | تهدئة الإساءة مع الحفاظ على الهيبة | الرد بإهانة أو تملق مبالغ |
| إيقاف التواصل | تسجيل طلب التوقف واحترامه | أي محاولة بيع أخيرة |
| التسليم البشري | الانتقال إلى موظف عند الطلب أو عند الحاجة | مقاومة طلب العميل |
| الإجابة المباشرة | الرد على السؤال من البيانات المتاحة أولًا | التهرب من السؤال بسلسلة أسئلة |
| الصوت الطبيعي | رسائل قصيرة ملائمة للسياق وليست محفوظة | سرد أسماء الكتب أو تكرار المجاملات |
| الخطوة التالية | خطوة واحدة تتناسب مع استعداد العميل | ادعاء إنجاز عملية لم يؤكدها النظام |
| الخصوصية | استخدام البيانات المصرح بها فقط | كشف تفاصيل عملاء آخرين |

## كيفية إرفاق المعرفة

يقوم `lib/aqarflow/sales-playbook.ts` بتصنيف الموقف الحالي، ثم تستدعي `lib/aqarflow/sales-knowledge.ts` البطاقات الموافقة لذلك الموقف. يُمرر هذا الاختيار داخل `sales_playbook` في حمولة التوجيه. هذا استرجاع سياقي بسيط قائم على تصنيف الموقف؛ ليس بحثًا دلاليًا في آلاف الكتب، وليس تدريبًا دقيقًا.

## الاختبارات

```bash
npm run test:aqarflow:sales-playbook
npm run test:aqarflow:sales
npm run test:aqarflow:migration
```

يجب إضافة حالات جديدة عندما تُكتشف ثغرة، مع إبقاء اختبارات الخصوصية، وطلب التوقف، وحدود الميزانية، وصحة معلومات العقارات حاسمة لا تُعوّض بنقاط إقناع أو تحويل.
